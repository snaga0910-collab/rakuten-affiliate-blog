# 比較記事の基準

このブログの記事は**数字を扱う記事**です。外部の添削で繰り返し指摘されたのは、文章力ではなく**計算の透明性**でした。以下はその指摘をルール化したものです。

書く前に読み、書いたあとに `npm run check` を通してください。

## いちばん大事なこと

**比較記事は「結論」より「再計算できること」が信頼につながります。**

読者が同じ数字を出せない記事は、どれだけ文章が上手くても比較記事として成立しません。文章表現をいじる前に、表と計算根拠を固めてください。

## 1. 計算条件を最初に明文化する

記事の冒頭近くに「計算のルール」の表を置きます。最低限これらを明記します。

| 項目 | 書くこと |
|---|---|
| 使用量・使用頻度 | 何を前提にしたか。複数パターンなら全部 |
| 初期費用 | 含めるか、含めないか |
| ランニング費用 | 電気代・送料など、含めるものと含めないもの |
| 最低注文量・最低利用期間 | 使用量だけでは支払額が決まらない場合の扱い |
| 調査日 | いつ時点の価格か |

**「同じ量で比較しました」と書くだけでは足りません。** 最低注文量があるサービスは、使う量を減らしても支払額が減りません。その場合は「使用量を基準にするが、支払額は契約条件に従う」と書き、個別に本文で説明します。

過去の失敗：水の比較記事で「同じ飲む量で計算」と書いたが、フレシャスには2か月連続で配送を止めると月1,100円の休止手数料があり、少量利用では支払額が減らなかった。

## 2. 数字を後出ししない

**冒頭で提示する数字と、比較表の数字の条件をそろえます。**

過去の失敗：「いちばん安い年3,900円」と冒頭に出しておいて、本文の後半で「本体が別に3,630円かかります」と書いた。読者から見ると数字の見せ方がズルい。

- 初期費用があるなら、**初年度の合計**を先に出す
- 維持費だけで比べるなら、**維持費どうしの比較だと明記**する
- 「N倍の差」と書くときは、**何と何を比べたN倍か**を同じ文の中で示す

## 3. 表の中で矛盾しない

表の「内訳」列に電気代と書いておいて、注記で「電気代は含めていません」と書くのは矛盾です。

**含めないものは、表に列を作って「別途」と書く**か、**表の直下に注記を置く**。FAQまで後回しにしないこと。重要なコストほど早く出します。

## 4. 一次情報を記事内で追えるようにする

「楽天市場を見ました」「当サイトの各比較記事で調べた実額」だけでは、この記事単体で根拠が完結しません。

**最低限これを書きます。**

- 調査した商品名・サービス名（一覧表にする）
- 調査日
- 送料込みか、税込か
- 計算式（`年間費用 ＝ 何＋何＋何`）

内部リンクは便利ですが、リンク先を読まないと計算根拠が分からない状態は避けます。

## 5. この記事が比較していないことを書く

**費用を比べた記事で、品質の優劣まで結論づけないこと。**

過去の失敗：水の記事で「差のほとんどは水質ではなく手間」と書いた。しかしこの記事は水質を比較していないので、水質差の重要度を判断する根拠がない。

正しい書き方：「今回の費用差の内訳は、水そのものの値段に加えて、冷水温水・配送・運搬の手間です。水質の優劣そのものは、この記事では比較していません。」

同じ型の失敗：

- 価格差だけを見て「香りに払う差」と断定（価格差の内訳は分からない）
- レビュー件数から「件数が増えると評価は下がりやすい」と一般論を導く（数件では証明できない）
- 「香りの好みが合うかどうかが全て」（単価・容量・素材も選択軸として残る）

## 6. 読者の判断を残す

「費用が同じなら配送のほうが合理的」のような断定は、読者の事情を無視しています。置き場所がない部屋なら結論が変わります。

**「〜な人には便利です。ただし〜な場合は別の選択もあります」**の形にします。

## 7. FAQは本文のコピペ置き場ではない

本文を読んだ人にとって新しい情報がないFAQは意味がありません。**検索意図の強い質問**を入れます。

良い例：

- 水道水をそのまま飲んでも大丈夫？
- 月に何L以上使えば得？
- 引っ越しが多い人はどれを選ぶべき？
- 浄水器は本当にペットボトルより安い？

悪い例：本文の見出しをそのまま疑問形にしただけのもの。

## 8. タイトル

- **32字以内**（検索結果で切れる）
- **比較対象が分かる**こと。「4通り比較」だけでは何の4通りか伝わらない
- 数字を入れるなら、本文の数字と条件が一致していること
- 「おすすめ比較N選」は使わない（大手比較メディアと同じ型で勝ち目が薄い）
- **タイトルの数字と、比較表の中身を必ず突き合わせる**

過去の失敗：「市販マウスウォッシュ6商品比較｜リステリン・モンダミン・GUM」と付けたが、中身は洗口液3つと歯間ケア3つで、GUMはフロスだった。記事の結論もフロス推しだった。

## 9. CTAは説明ではなく次の疑問につなげる

内部リンクを「くわしくは〜」で終わらせない。

```
悪い  くわしくは浄水器カートリッジ6商品の比較に書いています
良い  カートリッジの交換費用まで確認する →
```

読者が次に知りたくなることを先回りします。売り込む必要はありません。

## 10. 文章の癖

`npm run check` が数えます。閾値を超えたら直します。

| 項目 | 目安 | 理由 |
|---|---|---|
| 太字 | 1000字あたり6回まで | 多いと強調が強調として働かない |
| 同じ文末 | 15%まで | 意味ではなくリズムでAIっぽくなる |
| 「AではなくB」 | 1000字あたり1回まで | AI検出で上位に来る型 |
| 見出しの使い回し | 全記事の8割未満 | 全記事に同じ節があると型の印になる |

**「この記事が役に立たない人」は良い節ですが、全記事に置くと誠実さの印ではなくテンプレートの印になります。** 記事ごとに言い方を変えるか、置かない記事を作ってください。

## 書いたあとに必ず

```bash
npm run check
```

- **エラーが出たら直す**（アスタリスクの露出・タイトル32字超）。ビルドが止まります
- **警告は数えた結果**。閾値を超えた項目は直す

アスタリスクの露出は、閉じる `**` の直前が記号（`%` `）` `」`）のときに起きます。CommonMark の規則なので、日本語では自然に踏みます。直し方は `npm run check` の出力に出ます。

# 高得点だった記事から

外部監査で95〜96点がついたオーラルケアの記事（改訂版）で効いていた要素です。上のルールと重複しない部分だけ挙げます。

## 迷いに先に答える

記事の前半に、**読者がいちばん迷っていることへの答え**を置きます。商品の説明より前です。

```
見出し例  マウスウォッシュとフロス、結局どっちを優先すべき？
```

「AかBか」で迷っている読者に、**「両方だが、順番はこう」**と答えると、そのあとの比較が読みやすくなります。監査で「検索意図のど真ん中」と評価された箇所です。

## 選び方の基準を、比較表の前に置く

いきなり商品を並べず、**何で選ぶかを先に示します**。

```
① アルコールあり・なし（刺激）
② 成分の種類
③ 1回あたりのコスト
④ 使うシーン・携帯性
```

基準を先に読ませると、比較表が「意味のある表」になります。

## 比較表に入れる列

価格だけの表は評価されません。最低限これらを入れます。

```
商品 / 価格 / 1回あたりの目安 / 特徴（刺激・タイプ） / 使うシーン / おすすめな人
```

**「おすすめな人」の列があると、読者は数字を全部読まなくても自分に当てはめられます。** 余裕があれば「主な成分」「内容量」も足すと比較軸が増えます。

## 途中に小さなまとめを挟む

長い比較のあとに、3行程度のまとめを入れます。

```
携帯性で選ぶなら → モンダミン（約37円）
使用感を求めるなら → リステリン（約20円）
コスト重視なら → コンクール（約3円）
```

最後まで読まない人にも結論が届きます。

## 実体験は、使った商品にだけ書く

**使っていない商品に体験談を書かないこと。** 監査でもE-E-A-Tの観点で望ましいと評価されました。

使っていない商品は、レビュー傾向や仕様から評価していると分かる書き方にします。捏造するより、書かないほうが信頼されます。

## 結論で背中を押す

「自分に合うものを選んでください」で終わらせません。

```
悪い  自分に合う1本を選んでみてください
良い  まずは480円のGUMから始めるのがおすすめです
```

**いちばん外れにくい選択肢を1つ名指しする**と、読者は動けます。売り込みではなく、迷いを終わらせるためです。

## 記事末に参考文献をまとめる

本文中の「（参考: ◯◯）」だけでなく、**記事末に一覧**を置きます。公的機関の資料があれば必ず入れます。

## その他

- **タイトルの後半は検索ボリュームで選ぶ。** 「口臭対策」より「市販」のほうが検索される、といった判断が要ります
- **更新日を記事に表示する。** 価格が変わる記事は鮮度が信頼につながります
- **FAQは構造化データ（FAQPage）にする**（このサイトは実装済み）
- **内部リンクは、リンク先が存在しないうちは張らない。** 404に飛ばすほうがマイナスです
